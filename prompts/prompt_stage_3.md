# Stage 3: Add Expected-Value Comparison Probe

You are Claude Code working in the `ultimatum_arena` repository.

## Goal

Add a small script that compares:

- deterministic `ExpectedValueProposer`
- Gemma `expected_value`
- Gemma `payoff_table`
- optionally Gemma `deceptive` as a non-adaptive control

The purpose is to see whether Gemma can match a deterministic expected-value baseline before running a full sweep.

Preferred:

## Expected Behavior

The script should run only a small diagnostic comparison, not a full research sweep.

Default probe cells:

```python
[
    (0.0, 0.0),
    (0.25, 25.0),
    (1.0, 50.0),
]
```

Default rounds:

```python
10
```

Default seed:

```python
1
```

Outputs:

```text
outputs/expected_value_comparison_probe/<timestamp>/
```

The script should write:

- per-run JSONL and summary files
- `combined_summary.csv`
- `manifest.json`

It should print a compact table with:

- strategy
- audit_prob
- lie_penalty
- deception_rate
- acceptance_rate
- proposer_mean_payoff
- responder_mean_payoff

## Design Notes

For deterministic `ExpectedValueProposer`, use `run_experiment()` with a heuristic responder. Use the same responder style that approximates current LLM responder behavior, likely `ThresholdResponder(min_fraction=0.25)` or similar. Keep this explicit in the manifest.

For Gemma strategies, reuse `run_llm_strategy_sweep()` for `expected_value`, `payoff_table`, and optionally `deceptive`.

It is okay if deterministic and LLM rows are generated by separate runner calls, as long as the combined CSV has a clear `strategy` field:

- `calculator_expected_value`
- `expected_value`
- `payoff_table`
- `deceptive`
